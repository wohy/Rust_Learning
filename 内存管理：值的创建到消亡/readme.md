# 堆栈存储
互补
栈内存“分配”和“释放”都很高效，在编译期就确定好了，因而它无法安全承载动态大小或者生命周期超出帧存活范围外的值。所以，我们需要运行时可以自由操控的内存，也就是堆内存，来弥补栈的缺点

堆内存上是数据更为灵活，但是随之而来的问题是，堆上数据的生命周期如何控制

## 使用堆内存的场景
大部分来源于对动态内存大小的需求，才使用堆内存，少部分是对更长生命周期的需求，所以默认堆内存的生命周期也寄托在栈上，leaked 除外（不受栈内存生命周期的限制，使堆内存可以获得超出栈帧存活期的生命周期）

# 值的创建
- 创建位置：
栈：理论上，编译时可以确定大小的值都会放在栈上，包括 Rust 提供的原生类型比如字符、数组、元组（tuple）等，以及开发者自定义的固定大小的结构体（struct）、枚举（enum） 等
堆：数据结构的大小无法确定，或者它的大小确定但是在使用时需要更长的生命周期，就最好放在堆上
## 创建时的内存布局
### struct
为了让内存大小和访问效率最好，struct 中属性的存储位置会存在调整。会根据每个域的对齐（aligment）对数据进行重排。
原因：CPU 在加载不对齐的数据结构时，性能将显著下降
- 对齐规则：
1. 首先确定每个域的长度和对齐长度，原始类型的对齐长度和类型的长度一致。
2. 每个域的起始位置要和其对齐长度对齐，如果无法对齐，则添加 padding 直至对齐。
3. 结构体的对齐大小和其最大域的对齐大小相同，而结构体的长度则四舍五入到其对齐的倍数。
- 如下
```rs
struct S1 { a: u8, b: u16, c: u8,}
struct S2 { a: u8, c: u8, b: u16,}
```
rust 不进行自动重排优化的情况下（使用#[repr] 宏，来阻止其自动重排）， S1 占用空间为 6 （a 为 1，b 为 2，a和b 为对齐，将产生 1 的 padding，c 为 1，此时结构体长度为 5 ，而对齐大小为 2，结构体的长度需要四舍五入到其对齐的倍数，即为6），S2 占用空间为 4（a 为 1 ，c 为1， b 为 2，恰巧都符合规则，则无需重排），于 C 语言中的表现一致。自动重排后，S1 和 S2 占用的空间都为 4
